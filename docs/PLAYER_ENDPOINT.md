# 字幕来源修复（未发布候选，2026-10-30）

## #19/#16 对照与定位

经使用者授权，在原 Agent 身份、原持久账本和原请求头下进行一次最多 12 次 GET 的对照，未遇风险回复。两条反馈来源均出现：未签名 `/x/player/v2` 返回合法时间戳、正确 BV/CID，却提供与目标主题不符的字幕轨；签名 `/x/player/wbi/v2` 的正文与目标主题、时长相符。其中一条另做同路径 `/x/player/v2` 加签控制，字幕轨 URL 与签名 WBI 相同。字幕 CDN 不携带 Cookie；没有写入平台、来源库、手账或人格。真实标识、地址、正文与原始证据仅留本地。

这确认了错轨已存在于上游播放器响应中，本地缓存不是首次产生串台的环节；旧版会把该轨按目标视频保存并正缓存六小时，从而延续错稿。加签同时改变了请求参数与缓存键，无法据此确定服务端内部错误机制，也不能把两条样本推广为全部来源稳定。浏览器调用签名播放器入口的独立实现证据可参阅[公开 HAR 分析](https://github.com/gcnyin/bilibili-subtitle-api/blob/master/README.md)。

## 候选实现

- A1 固定获取 nav 公共 WBI 密钥，签名请求 `/x/player/wbi/v2`；`bvid`、所选分 P 的 `cid`、`wts` 均纳入 `w_rid`。没有未签名回退，也不在风控后刷新签名或切换入口。
- A2 仍在 A1 无可用文字且已有凭据时尝试，复用本次 nav 密钥。摘要/提纲不当作字幕。匿名基本成功路径为 view → nav → signed player → subtitle，共四次 GET；原 12 次任务请求限额不变，人工设置的较小上限仍可能提前停止。
- 匿名、无查询参数的 GET nav 可接受 `code=-101`、`isLogin=false` 且包含合法公共密钥的响应；这只是获取公开签名材料，不代表登录成功。带凭据的 -101、其他接口的 -101、HTTP 401/403/412/429、验证码与风险标记仍按原规则暂停。
- 播放器提供 BV/CID/aid 时比对当前元信息，冲突抛出 `SUBTITLE_SOURCE_MISMATCH`，不下载该轨、不转 A2、不缓存。缺少字段时如实记录空校验列表。真实错轨也可能回显正确字段，因此不是语义检测；不要求字幕 URL 含视频标识，实测合法轨存在不透明哈希路径（例如 AI 翻译轨）。
- AI 字幕文件名以 16 位以上数字开头时（AI 原语种轨的命名为 aid、cid 数字后接哈希），开头必须是本视频 aid 与所选分 P 的 cid，否则同样抛出 `SUBTITLE_SOURCE_MISMATCH`，不下载该轨、不转 A2、不缓存；核对通过时在 `identityFields` 记 `subtitleTrack`。这一条拦得住信封回显正确字段、字幕轨却属于别的视频的情况，但仍不是语义检测，不透明哈希名照旧不作要求。
- 播放器列出却没有地址的字幕轨被跳过，不再让整次读取以 `URL_DENIED` 中止；全部没有地址时按 A1 空结果处理，存在凭据时照常尝试 A2。
- 结果增加 `subtitleSource`，记录入口、`signing: wbi`、`cacheProtocol: 3` 和已比对字段；`semanticVerification: unverified`。不保存签名请求 URL、令牌或字幕 CDN 地址作为该标记。A3 复用的本次网络来源标记放在 `networkSource.subtitleSource`。
- read-v3 隔离旧 read-v1/read-v2 的全部缓存，包括可能的非空错稿。新正缓存仍为六小时，空/失败结果仍不缓存。不会自动修改既有来源、手账或人格；旧来源 ID 仍可读取，须由人类核对可疑稿及其派生记录。

## 验证与回滚

新增 16 项专项回归在旧实现全部失败，在候选通过；完整 253 项离线回归通过，0 跳过。包含独立签名向量、合法时间轴错稿、旧正缓存隔离、分 P 身份冲突、匿名密钥、A2 复用及风险/请求预算。最终候选包的隔离真实宿主验证结果另见[验收记录](ACCEPTANCE.md)。合成宿主调用与两条真实接口对照分别记录，均不代表全面真实观影验收。本候选尚未发布，公开包仍为 v1.11.3。

没有 schema 迁移。更新或回滚前停任务并备份完整私有 dataDir、配置和最新账号控制记录。回滚 v1.11.3 会恢复旧入口并可能重新使用仍未过期的 read-v2 错稿缓存，不能视为来源恢复；不要删除账本或暂停来绕过风险。存在明显内容冲突时停止据此提炼，由使用者按现有修订/撤回机制处理已有记录。

# 历史：字幕信息入口修复（v1.11.2）

2026-10-28，根据 [反馈 #13](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism/issues/13) 整理。本页描述 v1.11.2 对读取入口的修复；已有 v1.11.1 安装不会自动更新。发布结果与安装包校验值见本版 Release。

## 问题与改动

原 A1 直接向 `/x/player/wbi/v2` 发送 bvid/cid，没有 WBI 签名。反馈环境中这个请求返回 HTTP 412，而同一来源的 `/x/player/v2` 返回字幕轨。该对照是报告者的实测，本次维护只用合成响应复现这个分流，没有访问报告中的真实来源，不能推论所有 412 都由签名缺失引起。

A1 改为固定的 `/x/player/v2`，同步在传输层允许该精确 HTTPS 路径。沿用字幕轨选择、秒单位时间戳校验与来源页时长检查。匿名读取不新增 nav 请求，三次 GET 的基本取稿预算保持不变；有凭据时仍只向 API 发送本地已有 Cookie，不把它发给字幕 CDN。没有增加任意 URL 参数或模型可修改的 endpoint。

没有字幕或普通 API 不可用时，原来的签名 A2 流程仍可在已有凭据条件下运行。HTTP/API 风险回复仍立即中止，不能在 412 后改试其他接口、换 UA、账号、IP 或设备标识。本次不修改登录身份检查和账号写入权限。

## 验证与未决问题

六项新回归先在旧实现失败，再在候选通过；全套 219 项离线测试通过。夹具包含七段 from/to 小数秒字幕，也保留非法时间戳必须失败的检查。报告里的另一项 INVALID_TIMESTAMP 尚无可定位的合成输入，本次不把它视为已修复，更不通过忽略时间戳检查掩盖问题。

反馈还提到 GUI 与 CLI 的 URL_DENIED 不同。它们可能使用不同安装目录、profile 或版本；此处未确认具体原因。排查时核对实际宿主 profile、CLI 入口与同版安装包 SHA-256，不公开真实凭据、视频标识或日志原文。

发布门要求同提交 CI、包内容审计与该最终 tarball 的完整隔离真实宿主验收，实际完成结果见 v1.11.2 Release；真实平台兼容性没有在本次维护中验证。原版可复现的缺失签名请求与离线候选成功不能当成账号风控已恢复的证据。

## 升级与回滚

安装本版时，按 [Windows 安装说明](WINDOWS_INSTALL.md) 核对新版本与校验值，沿用原 DSH_HOME、profile 和私人 dataDir。升级、重启或回滚都不会自动清除已经持久保存的 HTTP_412 暂停；是否恢复仍由人类核实风险原因后决定，不能通过复制凭据、删账本或换目录绕过。

需要回滚时，备份实际 profile 的配置和清单，重新安装原先验证过的同版 TGZ，并恢复对应配置。保留手账、人格记录、消费回执、额度与风险暂停。旧包可能继续出现原先的入口问题，回滚不等于平台读取已经恢复。
