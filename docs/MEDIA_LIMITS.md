# 媒体时长与资源预算

v1.11.3（2026-10-30）补齐了图片交付层遗留的 600 秒校验。正式 v1.11.2 及旧版仍可能在已成功抽帧后返回 `VISUAL_PAGE_INVALID`；旧文档的“没有默认固定时长”没有涵盖这处遗漏。本版保留自适应抽样和总帧数 40，不通过放宽页大小或下载字节额度修复。验收与回滚见 [ACCEPTANCE](ACCEPTANCE.md) 和 [MAINTENANCE](MAINTENANCE.md)。

字幕和 A2 文字取稿本来就不受媒体时长上限限制。音频下载、本地 ASR、画面抽帧现在也不再默认按 600 秒或其他固定时长拒绝来源：在实际字节数、请求数和处理时间预算内能处理的长来源可以继续处理。

**其他资源额度保持。** 每任务最多 12 次请求、90 秒总时长、每次媒体响应最多 32 MiB，最高 480p、最多 40 张 JPEG、每张 2 MiB 及每页四张。长视频可能因文件太大或处理超时而返回相应预算错误；不会静默截成前十分钟。1.7.1 仅对 GET 传输异常最多尝试三次，抽帧可沿同清晰度/同尺寸备选 CDN 回退；每次尝试均计入原请求预算，超限、取消或风险立即停止，POST 不重试。不会放宽账号权限或解除暂停。抽帧时按全片时长增大采样间隔，未采样画面与声音始终属于未覆盖部分，不能把抽样成功称为完整观影。

## 可选人工限额

使用者如希望限制可处理的来源时长，可在实际 DSH profile 的可信插件配置中明确设置，保存后重载。例如只处理不超过 20 分钟的媒体：

```yaml
maxMediaSeconds: 1200
```

不填写时没有固定媒体时长上限。填写时只接受正安全整数；数值表示范围校验不构成另一个产品时长门。它是可信人工配置，模型工具、视频正文、评论或候选视频都不能自行设置或提高。CLI 从 `BILI_HUMANISM_CONFIG_FILE` 读取同名 JSON 字段：

```json
{ "maxMediaSeconds": 1200 }
```

原有本地 `limits.asrSeconds` 的显式限额仍有效，且不能超过同时配置的 `maxMediaSeconds`。`status.media.maxSourceSeconds` 为 `null` 表示未设固定时长上限，数值表示实际人工限额。

直接调用可选 `scripts/media.py` 时也不再默认限制为 600 秒；使用者仍可用 `--max-seconds` 明确设限。插件只转发经过校验的人工限额，并独立核对解码时长与来源元数据。整数来源时长允许最多一秒的解码精度差，但该容差不能越过人工限额。非法、非有限或超出安全表示范围的时长始终拒绝。

## 响应字节与时长的诊断（1.11.1）

`RESPONSE_TOO_LARGE` 表示单个响应超出字节上限，不是来源时长门。媒体响应固定最多33554432字节（32 MiB），API/字幕 JSON 固定最多4194304字节（4 MiB）。有 Content-Length 时报告声明值；流式超限时报告已读下限，不假称完整文件大小。错误不回显媒体 URL、签名、凭据或原始平台响应。CLI 与宿主采用同一安全错误序列化。

`status.media.mediaResponseBytes` / `jsonResponseBytes` 是以上固定响应上限，`taskRequests` / `taskWallMs` 是当前配置生效的任务预算，可能小于默认12次/90000毫秒。`maxSourceSeconds` 只描述人工时长上限：null 是未设固定时长门，数值是生效限额。来源较长可能带来更大的文件，但不能用一长一短的成败推算固定秒数上限；相同来源的不同音视频轨大小也不同。这里没有新增调高字节预算的模型参数或人工开关。
