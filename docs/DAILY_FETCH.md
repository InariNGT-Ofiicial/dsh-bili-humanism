# 每日取稿

从 1.8.0 起，每日取稿**默认关闭**。省略 `enableDailyFetching` 或设为 `false` 时，不创建取稿计时器、不发起每日取稿请求，也不占用当天尝试。已发布的 1.6.0–1.7.1 默认开启，需要立即关闭时请显式设置 `enableDailyFetching: false` 并重载。

只有本人在可信配置中显式设为 `enableDailyFetching: true` 后，插件才在 **DSH 宿主运行时**每天按北京时间（Asia/Shanghai）21:30 启动一次文字取稿，22:00 为硬截止。窗口内首次启动宿主会立即尝试；窗口外启动则等下一天。不会启动已关闭的 Desktop、唤醒电脑或补跑昨天的任务，也不依赖 Codex/Windows 定时任务。

同一次任务从现有热门候选入口取得最多 3 个候选，跳过账本中已有文字稿的来源、重复项与无效项，最多保存 **2 份新文字稿**。可设为 1 份；这是上限，不保证每天都有可用稿。无字幕且取不到 A2 文字、风控、超时或预算不足可能得到 0 份，状态会保留原因。部分字幕仍只代表已取得部分，不会自动补齐后半段。

每日取稿只预存 A1/A2 文字。它不调用模型、不下载音视频、不启动 ASR/抽帧，不生成信笺、人格选句或“已看过”的记录，也不调用历史、收藏、点赞、投币或评论。后续需要通过来源读取工具阅读已保存的稿件，手账与人格记录仍由原有流程决定。

## 配置

在安装此插件的同一 DSH profile 可信配置中修改，保存后重载。下面是**显式开启**的示例：

```yaml
- id: bili-humanism
  name: dsh-bili-humanism
  config:
    dataDir: /your/private/bili-humanism
    enableDailyFetching: true
    dailyFetchStart: "21:30"
    dailyFetchEnd: "22:00"
    dailyFetchLimit: 2
```

开始与结束必须为同一天的 `HH:mm`，结束晚于开始，时区固定 Asia/Shanghai；`dailyFetchLimit` 只能为 1 或 2。`enableDailyFetching: false` 加重载会停止后续调度并取消正在运行的宿主任务。模型工具不能修改这些设置、强制运行或清除当天记录。

默认值变更保留显式 `true` 的选择；如果之前已经填写 `true`，要关闭时须改为 `false` 并重载。关闭每日取稿不影响手动读取或默认启用的人格积累，不删除来源、手账、每日记录或风险暂停。

调用 `bili_humanism_status` 或本地 `bili-humanism status` 查看 `dailyFetching`：包括开关、窗口、下一次时间和 `lastRun`。`entries` 只有实际保存的非空文字来源 ID；`no_readable_new_sources` 表示 0 份，`partial` 表示保存了一部分后遇到预算或其他阻塞。`scheduled` 仅表示当前宿主的插件计时器在运行；单独本地 CLI 不会开启常驻计时器。

## 重启、截止与预算

同一私有账本每天持久记录一次取稿尝试，重启或两个宿主共用该账本不会重复取。当手动任务占用账本时，在窗口内每 30 秒延后检查，不消耗当天尝试；真正开始后的失败、空稿或中断当天不自动重试。不同 `dataDir` 是独立账本；多个 profile 要共用去重与每日记录，应由使用者明确指定同一私有 `dataDir`。

候选与逐条取稿共享 **12 次请求、3 个候选**上限，默认没有任务总时限；如设置了 `limits.wallMs` 则共享该人工限额，正文继续受每稿 token 额度约束。22:00 到达时取消请求；每次请求与保存前都检查截止，不在截止后提交新稿。风控暂停跨重启保持，调度不会解除暂停或自动换账号。取稿失败与零份结果不是学习完成的证据。
