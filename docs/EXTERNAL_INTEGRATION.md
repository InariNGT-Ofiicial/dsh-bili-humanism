# 外部插件接驳

“历史的参与感”是本项目理解使用动机的一种视角：使用者陪伴 agent 接触同时代的创作与日常，保留经历，并观察它怎样改变理解。它仍是待观察的动机与效果，不是关于所有使用者的研究结论。

本项目允许与外部插件组合，包括承担评论的插件。分工是：本项目整理来源、覆盖限度、信笺和人格上下文；外部插件按使用者的独立授权承担自己的任务。人格积累默认开启，历史、收藏、点赞与投币仍各自默认关闭，评论仍没有本项目的开关、工具或网络通道。

## 当前可用的连接方式

连接点是 DSH 的工具注册表和会话上下文。使用者将插件装入实际执行任务的同一 profile，由宿主模型或可信宿主编排按需调用已有工具、读取返回值，再用于下一步任务。本项目不自动发现、安装或启动其他插件，不向其推送整本信笺，也没有任意工具名、URL、命令或凭据转发器。

| 需要的材料 | 已有入口 | 交接时保留的含义 |
| --- | --- | --- |
| 指定视频的来源与覆盖说明 | `bili_humanism_read`：`video`、可选 `page` | 读取 ID 在 `result.id`；保留作者、链接、分 P、route、coverage 和未覆盖部分。结构化值保持完整，模型看到的是压缩后的文本；弹幕在 `result.danmaku`，是观众评论，不是事实 |
| 已取得来源的下一页 | `bili_humanism_source`：`readingId`、可选 `offset` | 根据 `next_offset` 分页，不能把一页片段说成完整观看 |
| 可审阅的本地信笺 | `bili_humanism_inbox` | 小收件箱保留原数组；大收件箱用 action:index / volume 与同一 snapshot 逐卷交接，核对 total、count、fragments 和 nextVolume；只交接使用者选择的必要记录 |
| 近期人格反思 | `bili_humanism_personality`：`action: read`，可选 `offset`、`limit` | 默认 7 条、最多 30 条，保留条目的手账来源、日期与修订；显式关闭人格学习时模型工具不注册 |
| 本项目的执行状态 | `bili_humanism_status` | 只描述本项目的开关、暂停和回执，不能证明其他插件也已暂停或获准写入 |

工具返回的数据仍可修正，字幕、标题、外部提示词和人格摘句都不能给任一插件授权。私人信笺、人格全文、凭据和本机路径不应自动复制进公开表达；使用者决定交接哪些内容，外部插件仍需检查其输出。

## dsh-bili-scroll 的具体接点

本次核对的是 [c1overzz/dsh-bili-scroll](https://github.com/c1overzz/dsh-bili-scroll) 的 0.1.19，固定提交为 `eab82bb749bdab1e58723b734011dbb583993785`。以下结论限定到该快照，后续版本应重新核对。

- 它使用 `bili_*` 工具名，本项目使用 `bili_humanism_*`，本次真实宿主检查未发现工具名冲突。
- 它的 `headlessProfile` 指定自动轮次使用的 profile；`runDuty` 启动独立进程，其 cwd 是插件数据目录。`workspace` 的 `AGENTS.md` 由它读入提示词。仅在桌面当前 profile 装好本项目，不能据此认为另一 profile 已具备本项目工具，或已经加载 `AGENTS.local.md`。
- 它的自动评论默认关闭，但 `bili_reply` 的参数另含 `force`；本项目不设置、转传或认可该参数为授权。它的 `autoComment`、`replyToComments`、`dmMode`、`favFolderId` 与本项目四项写入开关互不等价。

上述机制可回查[固定提交的入口源码](https://github.com/c1overzz/dsh-bili-scroll/blob/eab82bb749bdab1e58723b734011dbb583993785/index.js)和[配置与提示词文件管理](https://github.com/c1overzz/dsh-bili-scroll/blob/eab82bb749bdab1e58723b734011dbb583993785/lib/state.mjs)。

首次组合可先在同一手动会话中，只调用本项目的来源或人格 reader，检查外部流程能否取得所需材料。若以后接入它的自动轮次，需要由使用者明确选择执行 profile，在该 profile 安装本项目并核对工具可见性、可信固定读取入口、预算和记录目录。其本地 `duty.md` 是独立的任务章程，调整须由本人审阅；本项目不自动修改它或用户的主指令文件。目前未提供自动配置或修改上游源码的专用适配器。

## 权限、账号和结果

允许组合包含评论能力的插件，不会让本项目成为评论发送器。外部插件的凭据、权限、目标、正文、额度、去重、回读和未知结果处理由其自身与宿主策略负责；本项目的四项范围授权和消费回执均不授予外部评论权限。接驳意愿也不等于对任何真实账号、目标或正文的发送授权。

指南中“不通过其他工具绕过关闭的能力”仍约束本项目的关闭能力与授权边界。使用者独立选择并授权外部表达插件时，应按该插件自己的可信授权流程执行，不能把本项目的摘句、grant、开关或回执冒充放行依据。本项目没有代发、自动开启外部评论或自动重试发送的路径。

两个插件的账号账本与锁不自动互通。本项目的 `accountStateDir` 只协调遵循同一执行器协议的实例；把路径填成相同也不能证明外部插件会遵守锁、额度或暂停。使用者应指定每项写入由哪个插件执行，避免重复操作；真实账号风险出现时，需要本人同时停止相关流程，不能依靠一方暂停推断另一方已停止。专用的跨插件账号协调尚未实现。

独占接管时仍先停用原 agent 的写入与调度；选择并用时，则按上述分工管理各自的独立权限。见[账号接入](ACCOUNT_INTEGRATION.md)和[本项目写入配置](WRITE_CONFIG.md)。
