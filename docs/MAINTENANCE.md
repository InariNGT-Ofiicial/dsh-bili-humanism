# 维护、迁移与回滚

v1.11.3（2026-10-30）：移除图片交付层遗留的 600 秒元数据限制，保留生产抽帧的自适应间隔、最多 40 帧与四张一页。格式错误、越界时间戳、路径/哈希、下载字节、墙钟时间、人工时长预算和风险暂停仍检查。回滚到原 v1.11.2 会恢复超过 600 秒来源的交付失败；按下述步骤停任务并保留完整私有账本、人格、账号额度和暂停，不清空目录。

字幕误配反馈 #16/#19 尚未定位。HTTP 成功、覆盖比例或合法时间轴不能核实语义归属。对明显冲突来源先停止继续据此生成手账和人格，由使用者核对后按现有修订/撤回机制处理；不能自动批量删除已有私人记录。签名/未签名端点对照是报告者的观测，未在本次独立实测。禁止将时间戳夹取、换接口或重复读取当作已证实修复或绕过暂停的方法。

v1.11.3 包含的读取修复（2026-10-29 初验，基于 v1.11.2）：仅非空网络稿件缓存六小时；忽略旧空缓存，将空回复标为读取未确认，不增加自动重读。用户明确再次读取仍检查预算、凭据和持久暂停。音频仅沿上游提供的同码率备用地址尝试原白名单，遇风险、字节超限或额度耗尽立即停止。依赖版本、数据库 schema、平台写入开关和每日取稿默认值均未变。

v1.11.3 回滚：停止插件正在运行的任务，保留完整 dataDir 及最新账号控制记录，再校验并安装原 v1.11.2 包、重载同一 profile。没有数据库迁移，无需删除缓存、来源或手账。回滚会恢复旧版空缓存和音频仅主地址行为；不得通过删除账本、暂停、账号额度或更换目录绕过限制。发布门仍要求最终包隔离真实宿主验收与必需 CI，实际结果见本版 Release。

1.11.1（2026-10-26，基于 v1.11.0）：补充匿名 API 错误提示、响应字节诊断与 status 有效媒体预算；不修改错误码、端点清单、预算、模型工具参数或风险策略，无数据库迁移。回滚到 v1.11.0 仅失去新增提示和状态字段，保留私人账本、账号暂停及额度。升级不需要改配置；发布门包含同提交 CI 和最终包隔离真实宿主验收，完成结果见 v1.11.1 Release。

1.8.0（2026-10-25）：保存手账同时写入 `personality:review:*` 待办，当前 DSH agent 接续一次审阅；新增 `skip` 与实际选句日的 `personality:selected-on:*` 持久额度。沿用 schema=1，无批量补扫历史手账。关闭学习、取消和接续不可用不会唤醒其他会话；未完成记录可由 status/read 查看。回滚旧版会失去自动接续、skip 和实际选句日限额，但须保留待办、每日额度、来源日期条目及最新账号暂停，不删除 control 或用旧快照覆盖。再次升级后待办仍可审阅，旧日已完成的选择不重复输出。

1.8.0 同时包含默认值调整：每日取稿改为默认关闭，DSH 配置 schema 与运行时省略值均为 `false`；显式 `true` 继续开启，显式 `false` 保持关闭。更新并重载后生效，不改写用户配置，无 schema 迁移，不删除来源、手账、每日尝试、账号额度或持久暂停。回滚至 1.7.1 等默认开启的旧版时，需保留显式 `enableDailyFetching: false` 才能继续关闭调度。人格积累仍默认开启。

1.7.1 基于 v1.7.0，修复有界 GET 传输重试、同清晰度/同尺寸 CDN 回退及可选现有读取设备 Cookie；同时规范化 macOS 安装器测试的临时目录。共享请求数与总时长、媒体大小、允许清单、POST 单次发送和风险暂停保持。无 schema 迁移；增加设备 Cookie 时使用独立缓存身份，不删除旧缓存、来源、手账或账号状态。回滚到 v1.7.0 会失去重试/备选和读取设备支持，并可能命中原会话缓存；应停止任务后更换包，保留最新暂停、未知回执与额度，不能删除它们来恢复读取。发布前须通过三系统 CI 与最终包隔离真实宿主验收，完成证据见同版 Release 与[验收记录](ACCEPTANCE.md)。

1.4.1将 600k 调整为单次取稿的保守正文 token 估算，不累计会话 provider usage。人工 `maxReadTokens` 优先，未填写时兼容旧 `maxSessionTokens`，再省略则为 600000；旧显式 60000 仍为单次上限。缓存和 A3 复用按当前额度重新检查整份正文。旧的 token-session:\* / token-status 控制记录保留但不参与判断，不清除账号暂停、额度或未知回执，没有 schema 迁移。回滚到 1.4.0 会恢复会话累计语义，并需由本人将新字段改为旧 maxSessionTokens；回滚到更早版本还须遵守其配置范围。详见[取稿额度](TOKEN_BUDGET.md)。

1.4.0 候选新增最高 480p 视频与抽帧工具，尚待发布验收。SQLite schema 仍为 1；私有 control 记录保存来源绑定的帧索引、文件哈希和目录身份。自动取图共享文字读取任务的请求/总时长预算，`pythonPath` 只能由人类配置。下载产生的私有中间视频在本次任务 finally 清理；不删除输入原件、已有媒体或任何账本。硬终止遗留不做自动扫盘。回滚到 1.3.4 会失去自动取图工具，但须保留帧、来源、手账、人格记录及最新账号暂停/额度；不得用旧数据快照覆盖这些控制。

1.3.4 的字幕修复改为 A1 优先、A2 回退，并将读取缓存从 read-v1 改为 read-v2。升级后再次调用读取工具会按新顺序取稿，已有来源 ID 和手账不会自动改写；旧缓存不再命中，也不删除旧记录。回滚到 1.3.3 会恢复旧的 A2 优先行为，并可能继续命中尚未过期的 read-v1 缓存；无需删除账本或重置任何账号控制。

1.3.4 的音频与本地 ASR 复用修复不迁移 schema，也不删除缓存或改写既有来源。空网络结果匹配同视频、分 P、CID、时长的最近非空 A3；回滚后仍可按 A3 的已有 ID 调用 source，旧版 read 则可能再次返回缓存中的空结果。回滚也恢复旧的媒体允许清单，MCDN:8082 将重新被拒绝。账号暂停、额度、消费回执和人格记录不受该修复影响。

SQLite user_version=1；1.7.1 没有 schema 迁移。账号级状态目录须与本地数据目录一并备份。更新先停任务并保存私有数据目录的本地副本，验证 release 哈希与固定提交，再更换包。新版本遇高于自身支持的 schema 会拒绝启动。当前没有需要执行的历史迁移；未来迁移必须提供副本测试和明确回滚条件。

回滚：停止 DSH，移除插件，安装先前 release 包。若未来升级过数据库 schema，同时恢复升级前数据目录副本。回滚不清除账号风险暂停；保留副本的控制记录。不要在后台任务运行时替换账本。

CI 在 push / PR 上运行 Windows、Linux、macOS 的固定 Node 版本语法和离线测试；锁文件使用 npm ci。Dependabot 每周检查 npm 开发依赖和 GitHub Actions，更新先经过测试再合入。宿主契约升级由维护者在真实 DSH 验证后扩大兼容范围，不依赖宽泛 peer 版本自动追新。

版本发布流程：更新 package 与 lock、CHANGELOG 和验收记录 → 本地测试与真实宿主调用 → 打标签 → GitHub Actions 生成安装 tarball 与 SHA-256 → 发布预览版。没有 npm token 时不声称已发布 npm。本版支持 GitHub / release tarball 安装。

日常巡检应只读检查 CI、issue、依赖告警和官方 DSH/B站接口变化；有可重现 bug 时修复、测试并开出可审阅变更。没有具体 B站互动授权时保持零写入。用户请求的后续自动巡检使用 Codex 原生 heartbeat，无变化时安静，必要登录或决策阻塞再通知。

待完成的观察：7 天私人运行、至少 20 个代表视频覆盖与人工准确性审阅、独立 CLI 与桌面插件界面安装、真实 ASR/视觉链路、可选私人通知。它们不是本版本已经通过的测试。

历史与收藏在 1.1.0 实现，1.2.0 增加独立点赞与投币开关；手动账号接入继续保留，默认关闭，详见[配置](WRITE_CONFIG.md)。维护巡检不因此取得平台写入权限；真实写入验收仍须指定账号、目标与收藏夹。回滚到 0.1.0 可保留 schema=1 的数据，不用旧快照覆盖最新账号控制状态；持续保存暂停与待核对意图。

案例、手账、具体视频标识与演示截图保存在本地；GitHub 和 release 只保留通用代码、合成测试数据、安装说明和脱敏验收结论。
